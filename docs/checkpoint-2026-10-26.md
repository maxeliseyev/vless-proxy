## Что уже было проверено до этой сессии

По сообщению владельца, наш h3-прокси на тестовом VPS работает с клиентом
в РФ. Повторно доказывать применимость транспорта с нуля не требуется.
Приоритет следующего этапа — обычное HTTPS/HTTP/3-поведение публичного сервера
при активной проверке его адреса.

## Изменения в этой сессии

- Корневой Cargo manifest стал workspace с `crates/core`, `crates/cli`,
  `crates/server`, `crates/ffi`. Версия CLI и ядра остаётся 0.17.1.
- TUI, ротация журнала, службы и запуск sing-box/xray перенесены в CLI.
  Ядро предоставляет `serve_with_shutdown`, не запускает внешние процессы
  и не требует feature-флагов для исключения desktop-интеграции.
- Сохранены имена бинарников `vproxy`, `vproxy-server`, staticlib
  `libvproxy_ffi.a` и C API `ratatosk_*`. Импорт Rust-ядра — `vproxy_core`.
- Обновлены Dockerfile, CI, release workflow, проверка форка rustls,
  скрипт XCFramework и пути Swift/заголовков.
- Сервер обрабатывает обычные HTTP/3 GET/HEAD на том же QUIC-endpoint,
  сохраняя старую аутентификацию прокси. Прочитанные при распознавании
  байты HTTP/3-потоков возвращаются HTTP/3-обработчику.
- Контент поступает из заданного оператором `site_backend`, например
  `http://caddy:8080`. Поддерживаются потоковая выдача, Range, сохранение
  HTTP-статусов, HEAD и передача редиректов браузеру. Посетитель не может
  выбрать произвольный backend. При отсутствии настройки ответ 404,
  при недоступности backend — 502; методы кроме GET/HEAD получают 405.
- Добавлены проверки обычного HTTP/3-клиента, ошибок backend и заголовков.
  На соединении допускается до 32 одновременно обрабатываемых HTTP-запросов;
  чтение заголовков ограничено 5 с, операции с телом — таймаутом 30 с
  на чтение/запись, без загрузки всего ответа в память.

## Разделение публичного кода и конкретного сайта

Публичный сервер содержит универсальный HTTP/3-обработчик. Конкретные страницы,
выбор источника видео и параметры продуктивного сайта ведутся в отдельном
закрытом репозитории. Его локальная заготовка находится в `private/cover-site`,
исключена из Git основного проекта и Docker-контекста и имеет собственную
историю Git. Удалённый закрытый репозиторий пока не создан.

Измерительный стенд сохраняет нейтральную текстовую страницу. Страница
с видео ещё не создана, источник для ретрансляции не выбран. Подробные
требования и результаты поиска источников сохранены в `PLAN.md` закрытой
локальной заготовки.

## Границы этой рабочей точки

Локальные проверки перед сохранением:

- `cargo test --workspace --locked --offline`: 208 тестов, все прошли.
- `cargo clippy --workspace --all-targets --locked --offline` с запретом
  предупреждений и теми же исключениями Clippy, что в CI: прошло.
- `cargo fmt --all --check`: прошло.
- `cargo build -p vproxy -p vproxy-server --locked --offline` и запуск
  `vproxy --version` / `vproxy-server --help`: прошло.
- `cargo check -p vproxy-ffi --target aarch64-apple-ios --offline`: прошло.
- Swift-обёртки прошли `swiftc -typecheck` для iPhone SDK с новыми путями
  `crates/ffi/include` и `crates/ffi/swift`.
- `bash -n` для обновлённых скриптов сборки, стенда и синхронизации rustls:
  прошло.

Полная сборка XCFramework и запуск на iPhone в этой сессии не выполнялись.

- Изменения ещё не выпущены и не развёрнуты на VPS; номера версий не повышались.
- На стенде Caddy остаётся на TCP/UDP 443, наш сервер — на UDP 8445.
  Сам `vproxy-server` уже может обслуживать сайт на своём UDP-порту;
  общего публичного TCP/UDP 443 в развёртывании пока нет.
- `setup.sh` теперь добавляет `site_backend` в новый конфиг. Существующему
  конфигу параметр нужно добавить вручную, без регенерации остальных настроек.
- WebTransport для самого туннеля не вводился. Подготовленные ранее зависимости
  сохранены; их наличие не означает изменения протокола.
- Новая HTTP/3-часть ещё не проверялась настоящим браузером на VPS или
  в российской сети. Наличие сайта не доказывает устойчивость ко всем
  видам пробинга и не исправляет отпечаток QUIC-клиента.
- При внешнем Xcode-проекте обновить ссылки на `crates/ffi/include`
  и `crates/ffi/swift`; сам XCFramework сохраняет прежний путь.
